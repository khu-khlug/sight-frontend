# 그룹 일정 매주 반복 등록

그룹페이지 → 스케줄 → 일정 예약에서 신규 일정의 반복 옵션을 `매주 반복`으로 선택한다.
총 횟수는 첫 일정을 포함한 1~52회이며, 마지막 날짜를 등록 전에 확인할 수 있다.
각 일정은 같은 제목·장소·시간으로 기존 생성 API를 순차 호출해 등록한다.
수정 화면에는 반복 옵션이 없고, 생성된 일정은 각각 수정·삭제한다.

실패하면 이후 요청을 중단하고 완료 수와 남은 시작 날짜·횟수를 표시한다.
폼의 날짜와 횟수는 남은 일정 기준으로 갱신되므로 성공 응답을 받은 일정은 재등록하지 않는다.
응답 유실 등으로 서버 저장 여부를 알 수 없는 요청은 기존 API만으로 중복 여부를 보장할 수 없으므로 재시도 전에 목록을 확인한다.
등록 중에는 폼 입력과 중복 제출을 막는다. 화면을 떠나면 진행 중인 요청 이후 추가 등록을 중단한다.

## 자동 검증

Node 24 내장 테스트 러너와 TypeScript 타입 제거 기능을 사용한다. 추가 패키지는 필요 없다.
테스트 파일은 `dev/tests/*.test.mjs` 형식으로 둔다.

```sh
node --experimental-strip-types --test dev/tests/scheduleRepeat.test.mjs
yarn lint
yarn build
```

날짜 경계·윤년·시간대·잘못된 입력, 순차 호출, 부분 실패와 남은 일정 재시도, 화면 이탈 시 중단을 검증한다.

## 수동 검증

1. 두 API 환경 변수를 `/__mock-api`로 설정하고 `yarn dev`로 실행한 후 `/dev/group/1`을 연다.
2. 스케줄 → 일정 예약에서 매주 반복을 선택한다. 2026-12-25부터 총 3회이면 마지막 날짜가 2027-01-08인지 확인한다.
3. 등록 후 각 주에 같은 요일·시간·제목·장소의 일정이 한 개씩 표시되는지 확인한다.
4. 반복 안 함은 한 개만 생성하며, 일정 수정에는 반복 옵션이 없는지 확인한다.
5. 빈 횟수, 0, 소수, 53회, 빈 날짜는 등록할 수 없는지 확인한다.
6. 네트워크 속도를 제한한 상태에서 등록 중 입력·취소·재등록이 잠기는지 확인한다.
7. 두 번째 생성 요청을 실패시키면 첫 일정은 유지되고 이후 호출은 중단되는지 확인한다. 연결 복구 후 남은 일정만 등록한다.
8. 모바일에서 반복 옵션·요약·진행 상태가 폼 너비 안에 표시되는지 확인한다.
