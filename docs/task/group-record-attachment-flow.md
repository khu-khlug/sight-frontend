# 기록 첨부 파일 흐름 전환

## 작업 개요

기록 편집기의 첨부 파일(이미지·오디오·동영상·파일)을 편집 중 즉시 업로드하는 방식에서, 임시저장·저장 요청이 돌려주는 업로드 링크로 올리는 방식으로 바꾼다. 본문의 파일 블록은 기록 안에서만 유일한 식별자만 가지며, 조회 응답의 파일 매핑으로 실제 링크를 찾아 표시한다.

## 사용자와 목표

기록을 작성·수정하는 회원은 지금처럼 파일을 넣고 볼 수 있으며, 업로드에 실패하거나 편집을 버려도 서버에 쓰이지 않는 파일이 남지 않는다.

## 사용자 경험 계약

- 편집기에서 파일을 넣으면 크기 검사 후 로컬 파일로 블록을 만들고 곧바로 임시저장을 요청한다. 여러 파일을 한 번에 넣으면 임시저장 요청을 한 번으로 묶는다.
- 업로드 중인 블록은 진행 상태를 보여 주고, 업로드가 끝나면 실제 파일로 표시한다. 업로드에 실패한 블록은 실패 상태로 표시한다.
- 매핑에 읽기 링크가 없는 파일 블록은 404 미디어 블록으로 표시한다.
- 같은 그룹의 다른 기록에 있는 파일을 끌어다 놓으면 다시 올리지 않고 그 파일의 백엔드 파일 아이디로 참조한다. 다른 그룹의 파일과 채팅 첨부·저장소 파일·활동보고서 등 그 밖의 앱 안 파일은 원본을 받아 새 파일로 올린다. 끌어온 읽기 링크를 본문에 그대로 넣지 않는다(링크가 만료되고, 이 기록과 연결되지 않아 파일이 정리될 수 있다).
- 파일을 다른 파일로 바꾸려면 기존 블록을 지우고 새 블록을 넣는다. 같은 블록의 파일만 바꾸는 동작은 제공하지 않는다.

## 허용 및 제한 정책

정책 변경 없음

## 입력 및 복구

- 임시저장·저장 요청이 400(식별자와 파일 아이디 불일치, 다른 그룹·존재하지 않는·삭제된 파일 참조)으로 실패하면 본문을 유지하고 원인을 알린다. 정리되어 없어진 파일을 가리키는 블록은 사용자가 지우고 다시 넣어야 저장할 수 있다.
- 업로드 완료 알림이 206으로 일부만 성공하면 실패한 파일의 블록을 실패 상태로 표시한다. `NOT_UPLOADED`인 파일은 다시 업로드한 뒤 완료를 다시 알릴 수 있다.
- 임시저장이 409로 실패하면 기존 동작처럼 더 최신 임시저장이 있음을 알린다.
- 업로드에 실패한 블록은 사용자가 지우고 다시 넣을 수 있다.

## 데이터 및 연동

- 본문의 파일 블록은 `src` 등에 실제 주소 대신 기록 파일 식별자 토큰을 저장한다. 블록 속성에 백엔드 파일 아이디(새 파일이면 없음)를 함께 둔다.
- 기록 파일 식별자는 프런트가 만들며 한 기록 안에서만 유일하면 된다. 기존 기록의 임시저장은 그 기록과 같은 식별자를 쓴다.
- 임시저장 저장, 기록 작성, 기록 수정 요청에 본문과 함께 `files` 배열(`id`, `fileId`, 새 파일이면 `name`·`size`·`contentType`)을 보낸다. 배열에는 본문이 참조하는 파일 전체를 넣는다.
- 응답의 `uploads`(`id`, `fileId`, `uploadUrl`)를 받으면 해당 블록에 `fileId`를 반영하고 `uploadUrl`로 PUT 업로드한다. 반영된 `fileId`는 다음 저장 요청부터 함께 보낸다.
- 업로드를 마친 파일들의 `fileId`를 모아 `POST /groups/{groupId}/records/files/uploaded`로 알린다. 응답 200은 전부 성공, 206은 일부 성공이며 `results`로 파일별 결과를 확인한다.
- 기록·임시저장 조회 응답의 `files`(`id`, `fileId`, `url`, `name`, `size`, `contentType`)로 식별자→읽기 링크 매핑을 만들고, 파일 블록을 그릴 때 이 매핑에서 주소를 찾는다. `url`이 null이면 업로드가 끝나지 않은 파일로 보고 404 미디어 블록으로 표시한다. 매핑은 편집기 밖 상태로 두어 링크가 바뀌어도 본문을 바꾸지 않는다.
- 읽기 링크는 만료되면 기록을 다시 조회해 새 링크를 받는다.
- 지금의 "파일을 고르면 즉시 업로드"(`mediaInputState.ts`의 `processFile`)와 "앱 안 파일은 원래 주소를 그대로 참조"(`processRemote`) 동작을 위 흐름으로 바꾼다.
- 기록 첨부 업로드 링크 발급 API(`POST .../records/media/upload-link`)는 더 이상 쓰지 않는다.
- 개발용 Mock의 기록 작성·수정·임시저장 처리를 같은 계약으로 바꾼다.

## 사용자 보호 및 개인정보

다른 그룹의 백엔드 파일 아이디를 본문 블록에 넣어 보내지 않는다. 다른 그룹 파일은 새 파일로 올린다.

## 접근성 및 사용 환경

업로드 진행·실패·404 상태를 텍스트로도 알 수 있게 한다.

## 검증

사용자가 직접 브라우저에서 파일 삽입 직후 임시저장과 업로드, 업로드 실패 시 404 표시, 같은 그룹 파일 끌어다 놓기, 블록 삭제 후 저장 시 파일 정리, 기록 조회 시 매핑 표시를 확인한다. 요청에 따라 에이전트는 테스트와 브라우저 동작 확인을 수행하지 않는다.

## 비목표
